# Public Website — Backend gaps / سجل الترحيل

## ما تم تنفيذه

- تصحيح للنطاق المعروف، وليس فجوة جديدة: عنوان قسم رحلة الطالب ووصفه والعنوان الفرعي نصوص ثابتة معتمدة في الوضعين ولا تحتاج API إلزامياً. النصوص الأصلية مركزية في `lib/homepage-content.ts`. في Live، عناوين الخطوات الأربع وأوصافها فقط تعرض النص المعتمد متبوعاً بـ `(غير متوفر حالياً)` عند غياب القيمة الحقيقية؛ وفي Demo لا تظهر العلامة. الخلفية والخط الزمني والدوائر والتنسيق لم تتغير.
- `lib/homepage-journey.ts` نموذج عرض داخلي يقبل بيانات حقيقية محوّلة لاحقاً؛ ليس عقد API مقترحاً أو مستهلكاً. لا توجد طلبات جديدة أو نقطة وهمية، ولا إعادة محاولة وهمية لواجهة غير موجودة.
- Trust: أربعة مؤشرات بالترتيب: الخبرة، الجامعات، الوجهات، الطلاب. كل مؤشر يحتفظ بأيقونته الذهبية وخانة قيمته. توزيع 2×2 على الهاتف وأربعة أعمدة بدءاً من sm، وفواصل متكيفة. القيم الحالية غير متاحة؛ لا نستخدم عدد الوجهات المميزة كإحصائية أعمال.
- إزالة الحد الأدنى المصطنع لارتفاع بطاقة الصورة؛ ارتفاع البطاقتين أصبح بحسب المحتوى مع تمددهما الطبيعي إلى ارتفاع متوازن في الصف نفسه. خُففت الحشوات والفاصل دون إزالة العناصر.

## رسالة جاهزة لمطور الباك

يرجى اعتماد مصدر محتوى عام لخطوات رحلة الطالب في Homepage مع Lead: أربع خطوات مرتبة، بعنوان ووصف لكل خطوة. لا يوجد عقد متاح حالياً؛ يرجى تحديد المسار والحقول الفعلية قبل تكامل الواجهة. عنوان القسم ووصفه والعنوان الفرعي نصوص ثابتة معتمدة ولا تحتاج إضافة إلزامية. إلى حين التكامل تعرض خطوات Live النصوص الأصلية مع `(غير متوفر حالياً)`، والقيم الحقيقية تتقدم عليها تلقائياً بعد ربطها. هذا تصحيح للطلب السابق وليس متطلباً إضافياً.

نحتاج كذلك عقد إحصائيات موثقة لأربعة مؤشرات مستقلة: سنوات الخبرة، الجامعات، الوجهات الدراسية، والطلاب المسجلون. أسماء `trustStatistics.experience/universities/destinations/students` مقترحات فقط وليست حقولاً حالية. يرجى تعريف نطاق كل عدد ومصدره وتاريخ التحقق؛ عدد النتائج المميزة ليس إحصائية أعمال ولا يعني شراكات رسمية. لا تزودونا بأرقام تجريبية.

الصور الحالية للـHero وJourney معتمدة وتبقى ثابتة؛ إدارتها من الباك تحسين اختياري منفصل. بمجرد اعتماد عقد المحتوى والمؤشرات يمكن توصيل القيم إلى نفس مكونات العرض دون إعادة تصميم.

### طلب عربي جاهز — المتطلبات الجديدة فقط

نحتاج توسعة **استجابة الدولة الموجودة** `GET /api/v1/countries/{slug}` بعد اعتماد Lead، للفصل بين قسمين قائمين دون تغيير التصميم:

1. أربع قيم عربية قصيرة وموثقة لبطاقات معلومات الطلاب. المقترح `studentFacts` وفيه `studyLanguageAr`, `tuitionSummaryAr`, `admissionSummaryAr`, `applicationDatesSummaryAr`. هذه أسماء مقترحة وليست حقولاً حالية. يرجى تحديد السياق والمصدر وتاريخ التحقق للمعلومات المالية والزمنية؛ لا يُستخدم publishedAt كموعد تقديم.
2. دليل عملي منفصل ومفصل، بمقترح `studyGuide` من عناصر مرتبة `titleAr`, `introductionAr`, `stepsAr`, `displayOrder`. يغطي التحضير والوثائق والخطوات والحياة الطلابية، ولا ينسخ نصوص البطاقات المختصرة أو فقرة detailsAr.
3. نشر الأسئلة المعتمدة المرتبطة بكل دولة عبر **قدرة COUNTRY FAQ الموجودة بالفعل**؛ الدول الثلاث المفحوصة بلا أسئلة منشورة. لا نطلب endpoint أو علاقة جديدة للـFAQ.

لا نكرر هنا طلب الصور أو countryCode أو إحصائيات Homepage. بقاء الحقائق والدليل موسومين يعني أن التكامل المنظم ما زال ينتظر عقداً فعلياً؛ الصفحة Live-compatible وليست مكتملة المحتوى من الباك بالكامل.

### عنوان الرسالة: توثيق مصدر محتوى «من نحن» العام

قيل إن About API متاح، لكن OpenAPI العام المفحوص لا يعرض مساراً أو نموذجاً له، وSiteSettings لا يدعم محتوى التعريف. يرجى تزويدنا **بالعقد والمسار الفعليين** إن كانا منفذين وتحديث OpenAPI، مع تحديد النشر والاستجابة للغياب/عدم النشر، دون إنشاء API مكرر. إن لم توجد القدرة، نحتاج اعتماد مصدر About عام مع Lead؛ أسماء المحتوى **المقترحة فقط**: introductionAr للنبذة، storyAr للقصة، visionAr للرؤية، missionAr للرسالة، وvalues مرتبة بعناوين وأوصاف عربية، وحقول SEO عند دعمها. نحتاج النصوص المؤسسية المعتمدة، لا تكرار وصف واحد عبر الأقسام. الصورة التحريرية اختيارية وليست شرطاً؛ لا CMS للزخارف ولا طلب إحصاءات أو حسابات تواصل مكرر. الواجهة لا تستدعي مساراً أو تقرأ حقلاً مقترحاً قبل اعتماد العقد.
