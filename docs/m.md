=========================

- useState: لما نغيّر قيمتها، React بتعمل Re-render حتى تحدّث الواجهة.
- useRef: لما نغيّر .current،قيمتها ما بتعمل Re-render.
.current: منستخدمها لنقرأ القيمة أو نغيّرها بال useRef
ليش استخدمناها هون؟ حتى نمنع إرسال نفس الاستفسار مرتين بسرعة، بدون الحاجة لتحديث الواجهة.

قاعدة بسيطة: إذا تغيير القيمة لازم ينعكس على الشاشة، غالباً useState. وإذا بدنا نحتفظ بقيمة داخلية بدون تحديث الشاشة، ممكن نستخدم useRef.

- useState: تحديث القيمة مو فوري داخل نفس الـFunction، فممكن ضغطتين سريعتين يمرّوا قبل ما React تحدّث الحالة.
- useRef: تغيير .current فوري، فبتمنع الإرسال الثاني مباشرة.
يعني useState ممتازة لتحديث الواجهة، بس useRef أضمن كقفل لمنع الإرسال المتكرر بسرعة.

# ملخص الفرق بين`useState`و`useRef`بمنع تكرار الإرسال

## **1. استخدام`useState`

```
const [locked, setLocked] = useState(false);

async function submit() {
  if (locked) return;

  setLocked(true);
  await sendInquiry();
  setLocked(false);
}
```

**تسلسل التنفيذ:**

| الكود                 | شو بيصير؟                                                        |
| --------------------- | ---------------------------------------------------------------- |
| `if (locked) return`  | بيتحقق إذا الإرسال مقفول.                                        |
| `setLocked(true)`     | بيجدول تحديث الحالة، لكن ما بيغير القيمة فوراً.                  |
| `await sendInquiry()` | بينرسل الطلب وبتتوقف الدالة مؤقتاً.                              |
| أثناء انتظار الطلب    | React غالباً بتعمل Re-render وبتصير القيمة `true` بالعرض الجديد. |
| `setLocked(false)`    | بعد نجاح الطلب، بيجدول تحديث الحالة مرة تانية.                   |
| انتهاء الدالة         | React بتنفّذ التحديث وبتصير القيمة `false` بالعرض الجديد.        |

## **2. إمتى بتتحدث&#x20;**`useState`**؟**

- `setState` (دالة تحديث الحالة) بتجدول التحديث، وما بتغيّر القيمة فوراً.
- بالدوال العادية، غالباً بيصير Re-render بعد انتهاء تنفيذ الدالة المرتبطة بالحدث، مثل onClick أو onSubmit
- بوجود `await`، بتتوقف الدالة مؤقتاً، وبالتالي React فيها تعمل Re-render أثناء الانتظار وقبل انتهاء الدالة كاملة.
- حتى لو صار Re-render، استدعاء الدالة القديم بيضل محتفظ بقيمة الحالة القديمة. لحد ما يصير استدعاء جديد للدالة فلهيك حطينا setLocked(false) لحتى بالاستدعاء الجديد ما تكون تروو


مثلاً عندنا count قيمتها بالبداية 0:
const [count, setCount] = useState(0);

async function handleClick() {
  setCount(1);

  await new Promise(resolve => setTimeout(resolve, 2000));

  console.log(count); // 0
}

شو بيصير؟
1. بتنادي الدالة وقيمة count = 0.
2. setCount(1) بتجدول التحديث.
3. أثناء انتظار الثانيتين، React بتعمل Re-render (إعادة عرض)، وبتصير القيمة على الواجهة 1.
4. بتكمّل الدالة القديمة وبتطبع 0، مو 1
ليش؟ لأن الدالة بتحتفظ بقيمة الحالة من دورة العرض اللي اننشأت فيها.

يعني لما تعمل ريرندر بتتحدث على الواجهة اما بالدالة بضل عقيمتا القديمة لحد ما نستدعي الدالة مرة تانية


## **3. شو مشكلة&#x20;**`useState`**&#x20;بمنع تكرار الإرسال؟**

المشكلة بتظهر إذا استدعيت الدالة مرتين قبل تحديث الحالة اليوز ستيت قبل الريرندر يعني:

```
submit();
submit();
```

**ملاحظة مهمة:** المشكلة مو إنو الـRe-render بطيء. React عادةً بتحدّث الحالة بين ضغطتين منفصلتين من المستخدم. المشكلة هي احتمال استدعاء الدالة مرتين قبل تنفيذ التحديث.

## **4. الحل باستخدام&#x20;**`useRef`

```
const locked = useRef(false);

async function submit() {
  if (locked.current) return;

  locked.current = true;

  try {
    await sendInquiry();
  } finally {
    locked.current = false;
  }
}
```

**الاستدعاء الأول**

`locked.current = false`

تجاوز الشرط

`locked.current = true`

تغيير فوري للقيمة

إرسال الطلب

**الاستدعاء الثاني**

`locked.current = true`

`if (locked.current)`

`return`

منع الطلب المكرر


**القاعدة اللي لازم تتذكريها:**

- `useState`: لما بدي خزّن قيمة وتغييرها يحدّث الواجهة.
- `useRef`: لما بدي خزّن قيمة وأعدّلها فوراً بدون ما أتسبب بإعادة عرض الواجهة.

## شو الفرق بين ال useref , usestate :
الـRe-render مو تحديث فوري لحظة استدعاء setState، فممكن تنستدعى دالة الإرسال مرة تانية قبل ما React تنفّذ التحديث لان رياكت بتجدول التحديث لحد ما يتنفذ التحديث عند انتهاء الفانكشن او عندما يكون في عملية انتظار 

أما useRef فقيمتها بتتغير فوراً.

بس الفرق الأساسي مو سرعة تنفيذ الـRe-render، وإنما إنو useState بتجدول التحديث، بينما useRef بتعدّل القيمة مباشرة.
