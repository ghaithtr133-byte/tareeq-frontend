# Local browser visual checks

This is a development-only workflow for the running site at `http://localhost:3000/`. It uses Codex's existing in-app Chromium browser; it does not install packages, change the development server, or access production accounts. Use a new background tab, not the owner's open tab. Do not bypass a browser safety warning or a localhost access denial.

1. In a fresh browser-control session, inventory the browser surfaces. Select the in-app browser and open `http://localhost:3000/` in a separate background tab. Wait for `#hero-title` to be visible before measuring; a Next.js loading skeleton is not the rendered page.
2. Set the browser viewport to 390×900, 768×900, 1024×900, 1440×900, and 1920×900 in turn. At each size, save a JPEG screenshot under `test-artifacts/<run-name>/hero-<width>.jpg`. The entire `test-artifacts/` directory is Git-ignored. Check the saved image dimensions: if a wide viewport screenshot is narrower than `document.documentElement.clientWidth`, capture with `fullPage: true` and a top-of-page `clip` matching the document's client width.
3. Inspect each screenshot. For the Hero, confirm that the student and landmarks are visible, the Arabic copy and buttons are readable, the cards do not intersect the buttons, and the card arrangement remains usable. Compare the desktop composition with `design-references/approved-homepage.jpg`; do not treat a passing DOM measurement as a visual comparison.
4. For each viewport, inspect the rendered DOM: `document.documentElement.dir === "rtl"`; `scrollWidth <= clientWidth`; the Hero image has `complete === true` and `naturalWidth > 0`; the artwork's bounding rectangle has positive width and height; the title has no horizontal clipping; and the card region does not intersect either Hero CTA rectangle. Check visible images for failed loads as additional sections are tested.
5. Read browser console errors. On mobile, open and close the navigation menu and confirm its expanded state. Follow a local Hero CTA, confirm its destination, then use Back and confirm the homepage returns. Do not click the external consultation link during a visual-only test.
6. Reset the temporary viewport override and close the test tab. Keep the owner's tab and existing development server untouched. Report the exact viewport results, screenshots, browser errors, and anything that was not visually inspected.

The in-app browser supports agent-run verification, not a standalone CI test command. A local/CI Playwright runner would require separate approval before adding `@playwright/test` and its Chromium browser download.
